Local MCP runtime for spec-driven engineering

Make disciplined engineering observable.

TrueNorth-MCP is a protocol-first runtime for AI-assisted engineering. It keeps a repository’s workflow state on disk, exposes it through typed MCP tools and live resources, and verifies work from real command results instead of model claims.

Forked from bigpowers by danielvm-git. The inherited skill set is the foundation this project builds on; the Rust runtime is a clean-room implementation.

More than a prompt

Runtime-enforced

Typed tools record lifecycle transitions and tasks, run bounded verification, return operation receipts, and protect the machine-owned workspace with a writer lease and guarded write path.

Human-guided

Skills, specifications, architecture decisions, and review judgment help agents choose sound work. They stay readable, model-agnostic guidance rather than a claim that every recommendation is server-enforced.

The runtime is a local MCP stdio server for one repository worktree. It is designed for individuals and small teams, not a centralized policy service.

One loop, from context to integration

TrueNorth records the lifecycle so an agent can resume from current repository state, not a remembered conversation. The full process is documented in the lifecycle guide.

  1. Discover

    Read the live cockpit, current handoff, conventions, and repository context.

  2. Design

    Work from human-authored requirements and architecture decisions.

  3. Plan

    Record a task with a real command that will later verify the work.

  4. Execute

    Follow Red-Green-Refactor and preserve observable test evidence.

  5. Review

    A gate passes only when the server observed the configured command exit zero.

  6. Integrate

    Record the handoff, advance the phase, and begin the next engineering loop.

Capabilities that keep work grounded

  • Declared skill contracts

    Skills carry structured scope, side-effect, risk, and handoff information so the catalog and workflow can reason about their responsibilities.

  • Safe workspace lifecycle

    Initialization is non-destructive. Managed upgrades plan, validate, and apply owned changes transactionally while preserving local edits and specs/.

  • One writer per worktree

    A writer lease serializes mutations. Parallel mutating work uses separate Git worktrees and a separate MCP connection with its own TRUENORTH_ROOT.

  • Actionable gate failures

    Verification returns a bounded, redacted diagnostic excerpt. Truncated output is explicit, so callers know when to rerun the configured command locally.

  • Optional ontology tooling

    Projects can opt into a domain ontology resource and tools. It stays absent by default and never blocks a standard adoption path.

  • Compatibility by discovery

    Clients discover the available tools and resources, including feature-gated surfaces, instead of assuming every project enables every capability.

Start with a governed workspace

Bootstrap from an empty project directory, then inspect the available skill sets before connecting an MCP client. 

npx -y truenorth-mcp init --profile generic
npx -y truenorth-mcp skills list

Next, configure the wrapper as an MCP stdio server and set your project’s TRUENORTH_VERIFY_CMD. The install and connect guide has client configuration, platform support, and first-run details.

Clear boundaries

TrueNorth-MCP is not:

  • a centralized policy, authentication, or multi-user authorization service;
  • a hostile-command sandbox or a substitute for repository access controls;
  • a retained audit or compliance-record system; or
  • a coordinator for mutation over a shared network filesystem.

Git remains the durable collaboration and history boundary. See compatibility and troubleshooting for supported operating and recovery paths.
