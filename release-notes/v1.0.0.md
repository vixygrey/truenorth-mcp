# v1.0.0

## Highlights

- Establishes the v1 workspace, MCP, compatibility, and upgrade contract.
- Adds native runtime diagnostics through `truenorth-mcp --version` and `truenorth-mcp --check-config`.
- Publishes native release archives with checksums and retained verification records.

## Migration

1. Commit or back up the existing workspace before starting the upgrade.
2. Confirm `.agent/layout.yml` uses `version: "1"` and contains the required entries. A legacy workspace can omit the layout temporarily while it uses fallback reads.
3. Confirm `.agent/profile.yml` uses a supported profile. Omit it only to use the `issue-per-task` default.
4. Start v1, inspect `resources/list`, then read `truenorth://state` and `truenorth://cockpit` before any mutation.
5. Run the relevant workflow operation. The first write creates the v1 cockpit file under `.agent/`; the legacy `specs/` source remains unchanged.
6. Compare the new `.agent/` file with the committed legacy source. Confirm required and unknown fields are present before considering the workspace migrated.
7. Keep legacy files until the migration is reviewed and committed. Roll back by restoring the prior commit instead of editing an active cockpit in place.

Jev remains default-disabled, opt-in experimental infrastructure and is deferred from the v1.0.0 production surface.
