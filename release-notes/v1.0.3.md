# v1.0.3

## Highlights

- Isolates bounded gate execution from inherited credentials with an exact-name environment allowlist.
- Reports effective gate environment names through `--check-config` without exposing values.
- Corrects gate documentation to distinguish bounded execution from operating-system containment.
- Prevents lost cockpit updates with one mutating server per worktree, serialized requests, and stale-write detection.
- Adds versioned, bounded operation receipts to every repository mutation, including
  exact resulting-content digests and one-way MCP request correlation identifiers.
- Adds command-free gate receipts and ensures a TDD red timeout or signal cannot count
  as the expected test failure.
- Removes `.agent/telemetry/runs.yml` from the required layout and generated scaffold.
  Existing files remain accepted.
- Corrects full skill stocktakes to report usage evidence as unavailable when collection
  is disabled, rather than inventing zero-call rankings or timing conclusions.
- Defines the local, stdio, single-writer Git-worktree operating model for individuals and small teams.
- Removes the unsafe `harden-vps` skill from the source catalog and npm package.
- Removes the unused Allure reporting skill and its Allure-only planning metadata from the source catalog and npm package.
- Retires the `terse-mode` skill in favor of durable agent conventions and state-only session compaction.
- Retires the duplicate `simulate-agents` ceremony; `verify-work` owns user simulation and `request-review` owns independent critique.
- Retires `grill-with-docs`; use `grill-me` in docs mode for official-source validation.
- Retires `edit-document`; use `write-document` revise mode for existing documents.
- Aligns skill authoring templates and stocktake guidance with the runtime's prose and scripted validation schema.
- Pins release inputs by full commit SHA for third-party Actions, exact toolchains for Rust, Node, and npm, and locked dependency installations.
- Enforces dependency license policy in CI through `deny.toml` and Cargo Deny.
- Records builder environment metadata, toolchain versions, and lockfile digests in schema version 2 `RELEASE-VERIFICATION.json`.
- Converts GitHub Releases to draft-first publication and enables immutable releases at repository level.

## Migration

1. Run `truenorth-mcp --check-config` before restarting the MCP client.
2. Gate commands now inherit only `PATH`, `HOME`, `TMPDIR`, `TMP`, and `TEMP` by default.
3. Add each additional safe name required by the verify command to the comma-separated `TRUENORTH_GATE_ENV_ALLOWLIST` setting in the MCP client environment.
4. Remove credential-like, SSH agent, and `TRUENORTH_*` names. The runtime rejects them before it starts a gate process.
5. Restart the MCP client after changing its environment.
6. Run only one mutating TrueNorth server in each Git worktree. Use separate worktrees for parallel agents.
7. Before downgrading to a runtime that requires the telemetry placeholder, recreate
   `.agent/telemetry/runs.yml` as `runs: []`.

8. Development environments should install dependencies with `npm ci --ignore-scripts --no-audit --no-fund`.
9. Release builds require `--locked`. Published GitHub releases are immutable; changes require a new release version.

The bounded gate executor retains normal filesystem and network access. Roll back by removing `TRUENORTH_GATE_ENV_ALLOWLIST` and restoring the previous TrueNorth-MCP package version if a required tool cannot run with the restricted environment.
