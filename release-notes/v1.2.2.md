- Restricts cockpit migration recovery to validated cockpit targets and rejects corrupt journals before changing migration targets.
- Prevents resource and skill reads from following symlinks into private files or outside the repository.
- Rejects unsafe guard paths before Jev reads evaluation content or sends requests.
- Protects recovery lease creation and ontology seeding with descriptor-relative filesystem operations.
- Preserves Git diff guard checks for source filenames matching content-read exclusions without reading their contents.
- Adds versioned Jev benchmark inputs, explicit acceptance enforcement, and a protected manual provider-validation workflow.
- Keeps Jev production acceptance pending until approved thresholds, real-provider evidence, and published-artifact verification are available.
- Clarifies the historical rigor rubric and preserves 100 synthetic calibration candidates with separate reviewer rationales; these are not fresh qualification evidence.
- Adds a separately selected protected calibration workflow mode with an explicit estimated budget and aggregate-only evidence upload.
- Adds sanitized per-case rigor and drift diagnostics to benchmark report schema 2, with normalized scores, production classifications, hashed case IDs, and controlled errors.
- Calibrates opt-in Jev candidate defaults to separate credential material (0.25), complexity (62.5/100), and drift (0.50), without lowering import/convention boundaries or confidence gates.
- Preserves the distinct 100-case holdout and its provenance after its failed consumed provider run; new validation uses separate proposed-change fixtures.
- Keeps protected compatibility, calibration, and historical holdout workflow selections separate, without authorizing any paid rerun.
- Evaluates proposed guard content alongside bounded project context in MCP and stdin CLI; new files and missing parents are read-only inputs. Git modes remain offline metadata checks.
- Makes all Jev guard findings advisory while retaining deterministic protected-path and lexical denylist blocks, even on provider failure.
- Adds a separate 100-proposal full-guard qualification candidate, six zero-provider-call deterministic probes, versioned reviewer rationales, and an explicitly pending whole-guard policy; historical failed holdout remains unchanged.
- Adds separately selected, protected ten-proposal production MCP pilot and full-guard qualification workflow modes, with reviewed estimated budgets, response/transport accounting, and sanitized evidence only.
- Clarifies that the emitted hook needs canonical normalized proposal JSON and that automatic interception by an editing client has not been verified.

## Migration

Run `git ls-files -s` to identify tracked symlinks, shown with mode `120000`.
Replace resource and skill symlinks with regular repository files before reading them through MCP.
Supply repository-relative guard paths without traversal or symlink components.
A symlinked repository root remains supported.

Restore the previous regular-file content from version control if a replacement fails.
Do not downgrade to bypass the filesystem checks.

Benchmark report consumers must accept schema version `2` and its `case_diagnostics` field.
Fixture and acceptance-policy inputs remain schema version `1`.
Existing schema-1 reports cannot be expanded into per-case scores; any paid rerun requires separate authorization.

Jev projects without explicit overrides now use candidate defaults `secret_boundary: 0.25`,
`complexity_boundary: 62.5`, and `drift_boundary: 0.50`.
`rigor_failure_boundary` remains 0.70 and now applies only to imports and conventions.
To retain previous classifications, explicitly set `jev.secret_boundary` to your previous
rigor boundary, and preserve your previous complexity and drift boundaries in the same rules block.
Jev remains disabled by default; these pilot candidates are not a production-readiness claim.

To use the stdin guard, send canonical JSON with `paths` (1–100 repository-relative
targets), `content` (one proposed payload up to 1,000,000 bytes), and optional `task`; stdin is
limited to 8,000,000 bytes. The guard reads available safe repository context but never writes
the proposed files. `Allow` and `Annotate` exit zero with empty stdout and visible
advisories on stderr; deterministic `Block` exits one. Git `--staged` and `--range`
retain keyless metadata-only checks. An editing integration must normalize its own
write/replacement payload before invoking the hook; no arbitrary raw envelope is
accepted or automatic interception claimed.

The new `jev-bench guard-qualification` command does not replace the historical
evaluator benchmark. It writes a distinct schema-1 guarded aggregate under
`.agent/telemetry/jev-guard-qualification.yml` and never accepts offline fakes or
pending policy measurements as real provider qualification. See
`benchmarks/jev/README.md` for the review gates, budgets, and stopping conditions.
